# CUM engineering rules

The owner's direct instruction is to draft the whole project before running tests,
fixing failures, or optimizing. Do not report drafted checks as executed evidence.

All CUM application decisions belong in genuine eight-command Brainfuck under
`src/`. `host/bytehost/` is separately identifiable generic infrastructure. It may
implement binary transport, storage, standard cryptographic tool invocation,
process isolation, measurements and a generic workflow virtual machine. It must
never parse a source language, select a CUM transformation, or perform one.

The owner explicitly authorized committing and pushing this implementation draft
to `https://github.com/MrxSiN/CUM` in this session. This overrides the earlier
private-only instruction for the implementation source. Never publish credentials,
private recovery material, real job configurations or captured original projects.
Do not edit BBC or XAX to work around an unavailable compiler. Their existing
interfaces and limitations are dependencies, not promises of future capability.
Never invent textual XAX source. Reject unsupported adapters explicitly.

Keep evidence states separate: source written, compiled, executed, tested,
recovered, signed, measured and release accepted. Unknown evidence fails closed.
Do not add a CUM product version. Artifact format identifiers are permitted.
